# RESEARCH INDEX

**Purpose.** A working map of every research document: what it is for, its strongest usable rules (with
section references), where documents overlap or contradict, what is outdated or does-not-belong, and which
examples/interpretations are **not** automatically approved project decisions.

**Status of this document:** GOVERNED — production reference. Cites `READING_LEDGER.md` for processing
facts. Nothing listed here is approved project content; approval happens only via the
`DIRECTOR_CHARTER.md` loop and is recorded only in `CREATIVE_REGISTRY.md`.

**Scope note (2026-07-10):** two past-project files were removed — `One Piece Research 1.md` (Archon D.
Merdo bible) and `ONE_PIECE_RESEARCH_BIBLE.md` (SillyTavern RP dossier). This index now covers the seven
surviving craft-reference files. See `READING_LEDGER.md → Removed files`.

**Two standing rules this index enforces:**

1. **Established One Piece canon is the baseline setting/timeline of this project** (setting reference).
   But naming a canon character, place, or event in research does **not** approve any specific encounter,
   timeline divergence, relationship, or intervention. Those become project content only when Mert
   approves and locks them.
2. **Research examples and interpretations are not project decisions.** Deprecated original campaign
   material — including "Archon D. Merdo" (whose bible has now been removed) — stays non-canon unless Mert
   explicitly restores it.

## 1. `One Piece research 2.md` — "One Piece Operating Manual"

- **Purpose:** Reference for tone, English-script honorific/speech-register handling, layered political/
  institutional structure, and the two-axis (Devil Fruit + Haki) power model, with pass/fail checklists.
- **Strongest usable rules:**
  - Island-divergence: each new region changes ≥4 of 7 axes (currency, architecture, food, fashion,
    climate, polity, language quirk); "below four, it's a copy." (§3.5)
  - Build ≥7 institutional layers + aristocracy + sealed truth (§3.1).
  - Every power ships with a published, exploitable weakness; reveal the counter in the debut arc (§1,
    §4.5, §5.3).
  - Address-form change is a story beat (§2.6).
  - Bounties are political perception, not power level (§3.4).
  - Five fight anchors keep strong characters tense: personality, fear/reputation, skill, matchup,
    stakes-shift (§4.4).
- **Overlap:** two-axis power model overlaps files 2 and 7; character/villain grammar overlaps files 2–4.
- **Contradiction:** §1/§5.1 ("bad guys are wrong," reject moral-equivalence) vs §3.7 ("no faction is
  clean") — reconcilable (systemic greyness ≠ individual moral equivalence) but note wording tension.
- **Does-not-belong / outdated:** **§7 "DIRECTIVE — HAND THIS TO A WRITER OR AN AI" (L402)** — usable as
  **human authoring guidance only**; do not wire into any runtime prompt (this project runs no AI at
  play-time).
- **NOT-approved:** every island/faction/fruit/character named here is **real canon used as teaching
  reference** (setting reference only). "Your Wano-equivalent" style phrases are fill-in slots, not
  content.

## 2. `One Piece Research 3.md` — "Oda Operator's Manual"

- **Purpose:** Character-design operating manual — 12 Laws, visual/voice/interior/power/naming rules, plus
  a blank template and a gatekeeping checklist for original characters.
- **Strongest usable rules:**
  - Silhouette Law: identifiable in black-fill or redesign (Law 1, §2.1).
  - One Weird Thing: one asymmetric/broken/exaggerated feature per memorable character (Law 2, §2.2).
  - Name-Has-Roots: every name traces to a real pirate, a foreign word, or a sound-pun; "gibberish names
    die, sourced names live." (Law 5, §6.1)
  - Dream-Wound weld: specific impossible dream welded to a wounding person (Law 8, §3.6).
  - Power-Reflects-Person / strip test: "remove the fruit — is it the same person? If yes, the fruit isn't
    symbolic enough." (Law 9, §4.1, L294)
  - Every fight is an argument: write the one-sentence thematic clash first (§5.4).
- **Overlap:** silhouette/naming/epithet material overlaps files 1, 3, 4.
- **Contradiction:** none material; §2.6 sanctions a rare "open-mystery scar" exception to its own
  know-who-scarred-them rule.
- **Does-not-belong / outdated:** none. Part 8/9 forms feed `templates/PROTAGONIST_BRIEF.md` and the
  gatekeeping checklist.
- **NOT-approved:** §6.2 offers importing the canon "D." clan — a *design option* requiring Mert's lock,
  not a default. No invented project entities.

## 3. `ONE_PIECE_APPEARANCE_LAW.md` — Visual design grammar

- **Purpose:** Treats One Piece character design as a readable visual grammar (silhouette, body-type,
  face-hook, outfit, prop, comedy-deformation, crew-balance) portable without copying line style.
- **Strongest usable rules:**
  - One dominant silhouette anchor + one secondary accent; must read in black-fill and survive action
    posing (Rulebook A).
  - Body-type is casting: pick one extreme that telegraphs role/threat (Rulebook A).
  - One face hook beats ten subtle details; "memorable over handsome" (Rulebook A).
  - Outfit compresses status + occupation + island culture + danger/vanity/comedy + history (Rulebook A).
  - Designs must survive "ugly acting" — build in deformation permission (Visual comedy law).
  - Prop = the true logo: always present/implied, upgradeable without identity loss (Rulebook C).
- **Overlap:** silhouette shared with files 2 and 4 (dedupe when drawn into templates).
- **Contradiction:** none.
- **Does-not-belong / outdated:** the **web-export artifacts** (`citeturn…`, `entity[…]`, `image_group{…}`)
  — strip; never copy forward. Feeds `templates/VISUAL_DIRECTION_BRIEF.md`.
- **NOT-approved:** all examples are real canon (Luffy, Kaido, Franky, Hancock, Mihawk, real islands) used
  pedagogically — setting reference only. No invented project entities.

## 4. `ONE_PIECE_CHARACTER_NAMING_CHARACTERS_RESEARCH.md` — Naming & character grammar

- **Purpose:** Extracts a repeatable naming + character-construction grammar as laws, per-archetype
  category rules, failure modes, and a step-by-step creation template with validation tests.
- **Strongest usable rules:**
  - Newspaper/battlefield/nickname test for names (Name grammar).
  - Dream = a pointable noun phrase that fits a headline (Dream law).
  - Portable wound: changes ordinary behavior, not only flashbacks (Wound law).
  - Lovable / annoying / dangerous — set all three knobs deliberately (Tri-balance law).
  - Mechanized comedy: a repeatable loop tied to a wound (Comedy engine law).
  - Epithets are what outsiders notice first — write what the world says (Epithet/bounty phrasing).
- **Overlap:** naming/epithet overlaps files 1, 2.
- **Contradiction:** none.
- **Does-not-belong / outdated:** web-export artifacts — strip. Feeds
  `templates/CANON_ENCOUNTER_BRIEF.md`, `PROTAGONIST_BRIEF.md`, enemy/crew briefs.
- **NOT-approved:** all examples are real canon. **"Eldoria / Valethor" and "The Shadow Emperor of
  Oblivion" are explicit ANTI-examples of bad naming — never treat as proposed content.**

## 5. `ONE_PIECE_EPISODES_ANATOMY_RESEARCH.md` — Episode anatomy

- **Purpose:** Dissects landmark episodes into transferable structural/emotional craft laws, then
  translates them into prose technique for a "CYOA saga."
- **Strongest usable rules:**
  - Master arc engine: SUFFERING → COMMITMENT → DEFIANCE → LIBERATION (Part VI / Conclusion).
  - Fuse-and-detonation pacing: long emotional fuse, single climactic hit (Part I / III-A).
  - Scene opening law: "start on the second beat" (Part III-B).
  - Flashback fires once at maximum impact, triggered by present pressure (Part III-C).
  - Crowd reaction law: specific individuals, never "the crowd gasped" (Part III-G).
  - Ending-sting law: "end on the inhale" (Part III-J, Part V).
- **Overlap:** shares Beat-Breath-Burst and single-focus-climax with file 6.
- **Contradiction:** wants 800–1,000-word sustained threads — a scene-length target to confirm (the
  competing 350–500-token figure came from the now-removed SillyTavern dossier). Logged as a scene-length
  gate in `UNRESOLVED_DECISIONS.md`.
- **Does-not-belong / outdated:** none. Salvageable anti-slop/prose material feeds `WRITING_DIRECTIVE.md`.
- **NOT-approved:** all named entities are real canon; only unnamed illustrative prose snippets are
  invented (craft illustrations, not content).

## 6. `ONE_PIECE_FIGHT_LAW.md` — Fight rulebook + Prose CYOA adaptation

- **Purpose:** Twelve laws of One Piece combat grammar, then a dedicated guide for turning that grammar
  into **prose CYOA fights** — the most directly on-target file for this project's genre.
- **Strongest usable rules:**
  - Master principle: every fight answers a non-combat emotional question; state it first or the fight
    isn't ready (Part B).
  - **CYOA choice design: choices are character decisions, not tactical optimizations** — press/protect,
    adapt/observe, retreat/sacrifice — not "attack vs dodge left" (Part B, CYOA-specific).
  - Fixed vs variable: the emotional arc is FIXED; approach/style/cost VARY — "choose HOW they fight, not
    WHETHER it escalates." (Part B)
  - Loss is content, not game-over: a different path — wake somewhere new, owe a debt, lose a resource
    (Part B).
  - Persistent state: injuries, spent Haki/ammo carry across encounters (Part B).
  - Refuse-list guardrails: no fake-out deaths ("if a character dies, they stay dead"), boss fights ≤ 3
    phases, no mid-fight lecture circuits (Part B).
- **Overlap:** sibling to file 5; power/combat principles overlap file 7.
- **Contradiction:** none internal.
- **Does-not-belong / outdated:** none — natively on-genre. Feeds `templates/FIGHT_BRIEF.md`. A few
  chapter citations warrant a spot-check before any factual reuse.
- **NOT-approved:** all named entities are real canon used as examples.

## 7. `ONE_PIECE_POWERS_SCALING RESEARCH.md` — Power grammar

- **Purpose:** Codifies "power" as a language across six dialects (Devil Fruit, Haki, learned technique,
  tech/tools, environment, reputation) — 15 laws + creation rulebooks — so a saga scales by *problems*,
  not numbers.
- **Strongest usable rules:**
  - The move is the person: one non-negotiable constraint per fighter creates signature solutions (Law 1).
  - Keep powers singular, applications infinite; overbreadth is the #1 fake-fruit tell (Laws 2–3).
  - Every kit needs an embarrassment mode and an oppression mode (Rulebook B).
  - Two crisp weaknesses: one systemic, one situational (Rulebook B).
  - Power-ups land only after humiliation + constraint + vow (Law 10).
  - Scale by problems (escape, hostages, countdowns), keeping multiple tiers active (Law 11).
- **Overlap:** two-axis power model with files 1, 2; combat principles with file 6.
- **Contradiction (important to state precisely):** insists "**matchups are authored, not computed**" and
  brands computed tiers / "balanced kits" / procedural simulation as failure modes (Laws 3, 15). **This is
  a stance the project KEEPS** — outcomes are authored, branches are deterministic, the engine checks
  approved state to select authored scenes. It is **not** a conflict with deterministic offline operation.
  The genuinely open item (generic combat simulation vs authored state-conditioned branching) is logged in
  `UNRESOLVED_DECISIONS.md` as a technical-planning question.
- **Does-not-belong / outdated:** web-export artifacts — strip. Feeds `templates/DEVIL_FRUIT_BRIEF.md`.
- **NOT-approved:** all named entities are real canon.
